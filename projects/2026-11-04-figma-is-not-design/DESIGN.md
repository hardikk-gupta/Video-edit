# Proposed visual identity — One connected design map

**Status:** proposed for Hardik's review. This defines the look for the future HyperFrames composition; no composition HTML has been authored yet.

## Style prompt

Make the whole reel feel like one working design map laid across a warm studio desk. A single vermilion pencil line is the visual spine: it begins as a Figma frame, becomes a user flow, passes through questions and references, enters a coding-agent lane, then returns to a human decision. Keep the presenter in one stable lower panel while the map travels above. Every beat should feel like the next point on the same map, not a new template or unrelated scene.

## Palette

| Role | Colour |
|---|---|
| Paper field | #F1EEE7 |
| Main ink | #292823 |
| Journey line / decision mark | #C85E46 |
| Tool / interface blue | #566A92 |
| Quiet supporting line | #B8B1A4 |
| Presenter panel | #292823 |
| Presenter text | #F4F0E8 |

The blue is a neutral interface accent, not a recreation of Figma's brand palette. Use the warm paper as the main visual field and reserve the red-orange for the map path and decisions.

## Typography

- **Fraunces** for the spoken idea's display phrases: human, editorial, and clearly different from a product UI.
- **Space Mono** for agent names, flow labels, and code-like material.
- Use a restrained system sans for supporting copy only when necessary.
- Large phrase: 64–100 px on the 1080-wide master. Supporting labels: 22–30 px. Avoid decorative eyebrow labels and tiny metadata.

The serif/monospace contrast makes the human decision and the implementation tool read as different voices. It is not a permanent channel identity.

## Layout

- Canvas: 1080×1920 portrait, designed as a 58% visual map / 42% presenter split.
- The upper map remains one connected spatial system. The camera follows the vermilion route from node to node.
- Keep one continuous presenter instance below. The source footage has not been supplied yet; final crop and caption clearance depend on that footage.
- Captions are planned at the seam, with their exact position adjusted to keep the presenter's face clear.

## Motion

- The route is the transition: the camera tracks it, and each new visual grows from the current node.
- Draw path segments and connection lines on. Move the camera with the path rather than replacing the whole layout.
- Nodes enter with different purposeful movements; keep the map itself legible and stable while the camera travels.
- No random movement, looping timelines, generic floating cards, or disconnected scene changes.
- The final node holds on **OBSERVE · QUESTION · DECIDE**.

## Imagery and sourcing

- Draw original interface diagrams in HyperFrames. They are explanatory illustrations, not claims about real Figma, Claude Code, Codex, or Cursor screens.
- Use official product marks only if needed, and only next to the matching spoken name. No fake product screenshots.
- A reference-board beat uses real references chosen for the video after approval; no stock photography or unlicensed creator work.
- No AI-generated product interfaces, decorative 3D objects, or generic “AI brain” imagery.

## What not to do

- Do not say or imply that Figma is obsolete, or that design is only about taste.
- Do not frame the topic as “learn this now or die / fall behind.”
- Do not switch between unrelated visual styles or restart the story in separate cards.
- Do not place text over the speaker's face or use a Figma-like frame as if it were a real capture.
- Do not default to a large condensed headline, a decorative cross, tiny overlines, or paired rounded comparison cards.
